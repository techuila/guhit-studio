# Motion

Every interaction in Guhit Studio has a microanimation (DECISIONS D11). This file is the rulebook. Tokens live in `src/styles/tokens.css`. Craft guidance: the `design-motion-principles` skill in `.agents/skills/` (weight it as a productivity tool: restraint and speed first, polish second, play only in rare moments).

## Rules

1. Motion explains, it never delays. Input is never blocked while something animates. Every animation is interruptible and retargets from its current value.
2. Drags track the pointer 1:1, with zero smoothing or lag. Only the pick-up (lift) and the drop (settle) animate.
3. Duration follows frequency. Use the tokens, never raw numbers.

| Token | Value | Use |
|---|---|---|
| `--dur-press` | 80 ms | pointer-down feedback, keyboard-triggered changes |
| `--dur-hover` | 120 ms | hover, focus ring, small state changes |
| `--dur-base` | 180 ms | popovers, flyouts, tabs, toggles, sliding indicators |
| `--dur-panel` | 240 ms | dialogs, dock, inspector sections, view mode change |
| `--dur-scene` | 360 ms | rare: open project, AI proposal arrives, fit view |
| `--dur-loop` | 1600 ms | indeterminate progress only: a sweep, a spinner, the copilot's busy dots. Unchanged under reduced motion: those loops stop with `animation: none`. A loop is never shortened, because a near-zero period strobes. |
| `--tip-delay` | 350 ms | hover intent before a tooltip shows. Not motion, so reduced motion keeps it. |

4. Easing: `--ease-out` for anything entering or answering input, `--ease-in` for leaving (and leave faster than you enter: about 70% of the enter duration), `--ease-in-out` for moving between two places, never for the answer to a key or a click, because it starts slowly. `--ease-spring` only for something the user just placed or toggled: a placed element, a toggle thumb, a check mark, the pipe height handle. Pills, badges, counts, avatars and chips that appear use `--ease-out` from scale 0.9 (0.8 for dots), never from 0. The JS `ease.spring` (`src/ui/motion.ts`) follows the token's stops exactly.
5. Animate `transform` and `opacity` (and `clip-path`, `filter` sparingly). Never animate `width`, `height`, `flex-basis`, `max-width`, `margin`, `padding`, `left` or `top`. A pane or the dock never animates its size: the plan and 3D canvases would resize on every frame. Height reveals use grid-template-rows 0fr -> 1fr or a measured WAAPI animation. A sliding indicator may size itself with `width` and `height` only because it is absolutely positioned and alone in its layer.
6. Exits are animated too. Nothing pops out of existence: popovers, dialogs, toasts, flyouts, list rows, canvas elements.
7. Origin-aware: a flyout grows from its button, a dialog rises from slightly below, a toast slides from its edge, a tooltip fades from its anchor side.
8. One thing moves at a time per region. A list appears as one block (fade and 4 px rise, `--dur-base`). A row that arrives later rises alone. Stagger is kept for two rare moments only: the hub's cards on first load and a swarm's parts when the swarm starts, at most 30 ms per item and at most 8 items. Never stagger on a selection, a tab change or a panel that opens many times a day.
9. `prefers-reduced-motion: reduce` sets all duration tokens to ~0, and the global fallback (`src/ui/global.css`) runs every animation once with no delay, so no loop or stagger survives. Spinners and sweeps stop with `animation: none` and stay as a still mark beside their text. Canvas and three.js code must check `motionOK()` and jump to the end state.
10. No animation library. CSS transitions/keyframes, the Web Animations API, and requestAnimationFrame. Shared helpers live in `src/ui`: `motion.ts` (tokens in JS, easing, tween, usePresence), `motionDom.tsx` (Presence, sliding indicator, flash), `motionWaapi.ts` (grow in, collapse out, FLIP, origin transforms), `tips.ts` (the tooltip warm-up). Canvas and three.js keep their own small animators (`src/editor2d/anim.ts`, `src/viewer3d/engine/animator.ts`).
11. Purple (`--ai`) motion is reserved for AI, and nothing pulses forever. A copilot proposal's ghost breathes twice when it arrives (opacity 0.55 to 0.85, 1.6 s each), then holds at 78%, so the plan and the 3D view stop drawing. The 3D ghost's breath is a finite track (`src/viewer3d/engine/breath.ts`); the 3D animator has no looping track, so its frame loop always comes to rest. A working agent's dot is the teal "on" color with a steady ring (purple stays on proposals and the AI tag). Its plan cursor sends out one ring each time it starts a new step. The only loops in the app are indeterminate progress (`--dur-loop`), and they stop under reduced motion. Nothing rotates on hover, and there is no sparkle.
12. Content that swaps in place (the inspector on a new selection, a tab body, an editor's fields) cross-fades with opacity only: at `--dur-press` when a selection or a key caused it, `--dur-hover` otherwise. Only things that arrive (a new row, a note, a toast, a panel) rise, 4 px at most. Use the shared `ui-fade-in` and `ui-rise-in` keyframes (`src/ui/global.css`), not a local copy.
